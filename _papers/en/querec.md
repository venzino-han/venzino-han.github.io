#### Problem

Existing methods try to integrate the LLM and the recommender **serially** into a single model, which creates an information bottleneck and popularity bias.

<figure><img src="/assets/img/papers/querec-architecture.jpg" alt="Serial vs. parallel architecture: the parallel design turns the dual-perspective bottleneck into synergy"><figcaption>Serial vs. parallel architecture: the parallel design turns the dual-perspective bottleneck into synergy</figcaption></figure>

#### Approach

- Use the LLM's own **query-generation** ability to build a personalized query for each user.
- Integrate the LLM **in parallel** with the recommendation model instead of in series.
- Achieve high performance **without LLM training or a separate alignment stage**, and plug in new LLMs or black-box models easily.

<figure class="fig-half"><img src="/assets/img/papers/querec-queries.jpg" alt="Personalized user queries generated by QUERec (also improving explainability)"><figcaption>Personalized user queries generated by QUERec (also improving explainability)</figcaption></figure>

#### Results

- Higher accuracy and personalization than serial integration.
- More diverse recommendations, reducing popularity bias.
