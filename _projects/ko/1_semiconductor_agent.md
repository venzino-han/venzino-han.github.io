**역할:** 프로젝트 리드 — 문제 정의와 연구 방향 설정부터 Mock API Sandbox, 벤치마크 및 데이터 생성 파이프라인, 하네스 개발, Rollout 실험과 실패 분석까지 전 과정을 주도했습니다.

#### 문제

실제 장비 환경에서는 네트워크 연결이나 외부 대형 모델에 의존하기 어렵고, 제한된 연산 자원에서 **On-Device**로 동작해야 한다는 제약이 있었습니다.
따라서 더 큰 모델을 사용하는 방식보다, **소형 언어모델(SLM)** 자체의 성능 한계를 어떻게 보완해 장비의 도구를 안정적으로 호출하게 할 것인지가 핵심 과제였습니다.

#### 접근

- 실제 장비 인터페이스를 모사한 **Mock API 기반 Sandbox**를 구축해, 실제 장비를 반복적으로 사용하지 않고도 대규모 Tool-calling 실험과 실패 원인 분석이 가능하도록 했습니다.
- 사람이 직접 정의한 핵심 작업 시나리오를 seed로 삼아 LLM으로 다양한 상황으로 확장하는 방식으로 **벤치마크**를 만들었습니다.
- LLM 생성 데이터의 양을 늘리는 것만으로는 성능이 충분히 향상되지 않았고, **실패 사례 분석** 결과 문제의 핵심이 개별 태스크보다 여러 도구를 어떤 순서로 조합할지 결정하는 **계획(Planning)** 과정에 있음을 확인했습니다.
- **계획과 실행을 분리한 하네스**를 설계해, 계획 단계에서는 필요한 도구와 장비 정보를 검색해 제공하고 실행 단계에서는 계획된 작업에 집중하도록 했습니다.
- **실행 결과 검증**과 함께, 동일 과제를 **여러 번 독립적으로 Rollout**한 뒤 실행 결과의 **일관성**을 기반으로 신뢰도가 높은 결과를 선택하는 구조를 결합했습니다.
- 이와 함께 장비 지식 RAG·검증 기반 답변 신뢰도 강화, 사전학습 비전모델(VLM, SAM3 등)을 활용한 zero-shot 불량 유형 분류 연구를 수행했습니다.

#### 결과

추가적인 대형 모델 의존 없이 **On-Device 소형 모델의 Tool-calling 성능과 안정성을 크게 향상**시켰습니다.
이 경험을 통해 도메인 데이터를 구조화하고 Sandbox와 평가 체계를 함께 설계하여 실제 환경에서 AI의 신뢰성을 높이는 역량을 쌓았습니다.
